# 仪表盘金额右边界修复设计

## 问题

仪表盘主金额在显示 `¥157.52` 等内容时，最后一个数字的右侧笔画被裁切。截图中金额右侧仍有充足的面板空间，因此问题不是容器宽度不足，而是文本自身的绘制边界过窄。

## 根因

主金额使用 38pt 黑体等宽字体，同时应用 `.tracking(-2)`。负字距缩短 SwiftUI 为 `Text` 计算的横向边界，但最后一个粗体数字仍需要完整的字形绘制宽度，导致末尾字形被 `Text` 自身裁切。

## 方案比较

1. **移除负字距（采用）**：修复造成错误测量的源头，保留字号、格式、单行显示和自动缩放。
2. **增加尾部 padding**：只能补偿当前字号和字形，未来字体或金额格式变化后可能再次裁切。
3. **缩小主金额字号**：能够避开问题，但会削弱仪表盘最重要的数据层级。

## 实现

- 删除主金额文本上的 `.tracking(-2)`。
- 保留 38pt 黑体等宽字体、`.contentTransition(.numericText())`、`.monospacedDigit()`、`.lineLimit(1)` 和 `.minimumScaleFactor(0.68)`。
- 添加源码契约回归测试，限定主金额代码段不得再次使用负 `tracking`。
- 不修改金额格式、累计逻辑、面板宽度或其他文字样式。

## 验收

- `¥157.52` 的最后一个数字完整显示。
- 更长金额仍保持单行，并在空间不足时使用现有自动缩放。
- 现有功能测试、Release 构建、Info.plist 和代码签名验证通过。
