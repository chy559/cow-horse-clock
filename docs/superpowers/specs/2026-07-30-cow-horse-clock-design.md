# 牛马时钟 macOS 菜单栏应用设计

日期：2026-07-30
状态：已批准

## 1. 产品目标

牛马时钟是一款 macOS 14 及以上系统使用的原生菜单栏应用。用户设置日薪、每日工作时间和工作日规则后，应用在有效计薪时间内实时显示今日已经赚取的金额，让抽象的工作时间变成可见、持续增长的“搬砖资产”。

第一版的成功标准：

- 点击菜单栏图标后立即展开紧凑仪表盘，点击外部时自动收起。
- 今日收入、当前计薪状态、工作进度和下班倒计时一眼可见。
- 金额在午休、下班后和休息日停止增长，电脑休眠或应用退出后仍能正确恢复。
- 用户可查看本月累计、历史总计和每日收入记录。
- 日薪或工作时间的修改不会改写已经结算的历史收入。
- 应用完全本地运行，不依赖网络或账户。

## 2. 平台与技术路线

- 平台：macOS 14 Sonoma 及以上。
- UI：SwiftUI。
- 菜单栏容器：`MenuBarExtra`，使用系统弹窗行为，失焦自动收起。
- 本地设置：轻量偏好设置存储。
- 历史收入与日历例外：Codable JSON，本地存入应用偏好域。
- 图表：Swift Charts 或等价的原生轻量实现。

选择原生 SwiftUI 是因为它能以更低的运行开销提供系统一致的菜单栏行为、登录启动和本地数据能力。第一版不引入 WebView、Rust 或跨平台运行时。Codable JSON 足以承载按日增长的小型账本，也让项目在只安装 Apple Command Line Tools 的机器上保持可构建。

## 3. 信息架构与界面

### 3.1 默认仪表盘

默认面板是用户每次打开应用看到的首页，信息层级如下：

1. 今日已赚金额，作为最大字号的主视觉。
2. 当前每秒收入和计薪状态。
3. 半圆机械仪表盘，显示今日工作进度。
4. 距离下班或下一计薪节点的倒计时。
5. 今日进度和本月累计两个摘要卡片。
6. 设置和累计账本入口。

弹窗保持紧凑，不提供常驻桌面窗口。

### 3.2 累计账本

累计账本包含：

- 本月累计收入。
- 历史总收入。
- 当月每日收入柱状图。
- 每日收入列表和结算状态。
- 上一个月、下一个月切换。

当天尚未结算时，页面动态显示“历史已结算金额 + 今日实时金额”，并将当日标记为“搬砖中”。

### 3.3 设置

设置项包含：

- 每日薪资，第一版固定使用人民币。
- 上午计薪开始和结束时间。
- 下午计薪开始和结束时间。
- 默认工作日，初始值为周一至周五。
- 工作日历，用于手动标记休息日和加班日。
- 登录时启动开关。

所有数据仅存储在用户本机。

## 4. 视觉与文案

视觉方向为“打工人 punch card”：

- 奶油黄色主背景、黑色粗描边、橙红强调色。
- 卡片采用略带印刷物和打卡纸的造型。
- 金额使用等宽数字字体，保证实时变化时视觉稳定。
- 仪表盘使用机械刻度、实体指针和克制的弹性动画。
- 装饰性元素不与金额和倒计时争夺视觉优先级。

不同状态使用轻松但不影响理解的文案：

- 上班前：“工位引擎尚未点火”。
- 工作中：“每秒回血 ¥X”。
- 午休：“暂停燃烧生命”。
- 下班后：“今日自由已到账”。
- 休息日：“今天不当牛马”。

## 5. 计薪规则

### 5.1 有效工作日

判断优先级：

1. 日期被手动标记为休息日时，不计薪。
2. 日期被手动标记为加班日时，计薪。
3. 未设置例外时，根据默认工作日判断。

第一版不联网同步中国法定节假日和调休安排。

### 5.2 有效计薪时间

每天包含两个独立时段：

- 上午工作时段。
- 下午工作时段。

午休不计薪。上班前、下班后和非工作日不计薪。

当日总计薪秒数为两个时段时长之和。每秒收入为：

```text
每秒收入 = 当日日薪 ÷ 当日总计薪秒数
```

今日实时收入为当前时间之前落在两个有效时段内的秒数乘以每秒收入，并限制在零到当日日薪之间。

### 5.3 实时重算

应用不保存一个每秒递增的计数器，而是根据当前时间和当日配置重新推导金额。这保证以下情况不会造成累计漂移：

- 应用退出后重新打开。
- 电脑休眠后唤醒。
- 系统计时器被延迟。
- 用户手动调整系统时间。
- 跨越午休、下班或午夜。

金额显示保留两位小数；内部计算使用适合货币的十进制表示，避免二进制浮点误差。

## 6. 历史结算与配置变更

每个有效工作日对应一条收入记录，记录该日实际采用的日薪、工作时段、日历类型和最终收入。

- 已结束日期的记录不可因后续配置变更而重算。
- 当天记录在展示时保持动态；日期结束后转为已结算记录。
- 修改日薪和工作时间从保存后的当前日期生效；当前日期的实时收入会使用新配置重新推导整日金额，未来日期沿用该配置。
- 当日最终记录保存最后一次生效的配置快照。已经结算的更早日期不受影响。
- 历史累计等于所有已结算记录加上当前日期的实时收入。
- 首次完成设置时将当天记为追踪起始日，不补算安装应用之前的收入。
- 应用启动或跨过午夜时执行账本对账：从最后一次对账日期开始，为遗漏的有效工作日生成结算记录，再计算当天实时收入。应用连续关闭数日后，累计金额仍会补齐。

## 7. 组件边界

### `CowHorseClockApp`

管理应用生命周期、`MenuBarExtra`、SwiftData 容器和全局依赖注入。

### `DashboardView`

渲染今日金额、当前速率、仪表盘、状态文案、倒计时和摘要卡片。它只消费视图状态，不直接执行计薪计算或数据写入。

### `EarningsEngine`

纯计算模块。输入为日期、当前时间、日薪、两个工作时段、默认工作日和日历例外；输出为：

- 今日收入。
- 每秒收入。
- 已完成比例。
- 当前状态。
- 下一状态切换时间。
- 下班倒计时。

该模块不依赖 UI 或数据库，可通过确定的时间输入进行完整单元测试。

### `LedgerStore`

负责创建和读取每日结算记录、按月份聚合、计算历史总计，以及防止配置变更改写既有记录。

### `ScheduleStore`

负责默认工作日、工作时段和日期例外。对外提供某一天的有效日程快照。

### `SettingsView` 与 `WorkCalendarView`

负责编辑和验证设置。无效设置不会提交到存储层。

## 8. 数据模型

### `WorkSettings`

- `dailySalary`
- `morningStart`
- `morningEnd`
- `afternoonStart`
- `afternoonEnd`
- `defaultWeekdays`
- `launchAtLogin`
- `trackingStartDate`
- `lastReconciledDate`

### `CalendarOverride`

- `date`
- `kind`: `rest` 或 `work`

同一日期最多存在一条例外记录。

### `DailyEarningRecord`

- `date`
- `salarySnapshot`
- `scheduleSnapshot`
- `dayKindSnapshot`
- `earnedAmount`
- `settledAt`

日期在记录集合中唯一，防止重复结算。

## 9. 验证与异常状态

保存设置前验证：

- 日薪必须大于或等于零。
- 每个时段的结束时间必须晚于开始时间。
- 上午结束时间不得晚于下午开始时间。
- 当日总计薪时长必须大于零。
- 至少选择一个默认工作日，除非产品未来增加“仅手动加班日”模式。

无效字段就地显示原因，保存按钮保持禁用。数据读取失败时，主面板显示安全的零金额和简洁错误提示，不写入推测出的历史记录。

首次启动时先显示简短设置引导；保存有效设置后进入仪表盘。

## 10. 测试策略

### 单元测试

- 上班前、上午工作、午休、下午工作和下班后的金额。
- 工作日、周末、手动休息日和手动加班日的优先级。
- 时段边界、午夜切换和月份切换。
- 休眠后按当前时间重算。
- 调整系统时间后不出现负数或超过日薪。
- 修改日薪后不改写历史结算记录。
- 应用关闭数日后重新启动，可以补齐追踪开始日之后遗漏的工作日记录。
- 金额十进制精度和两位小数显示。
- 同一日期不会重复结算。

### 界面测试

- 首次启动设置流程。
- 点击菜单栏图标显示仪表盘。
- 主面板进入账本和设置后可以返回。
- 无效设置无法保存并显示原因。
- 工作日历可以创建和取消休息/加班标记。

## 11. 第一版范围外

- 云同步和账户系统。
- 联网节假日或调休同步。
- 通知提醒和下班音效。
- 多币种。
- 常驻桌面窗口。
- 团队、排行榜或社交功能。
- iOS、Windows 或 Web 版本。
