# 人生大事设计

## 目标

新增一个与薪资仪表盘、搬砖账本、设置和专注倒计时完全独立的“人生大事”页面。用户可以按日期记录重要事件的描述与类型，并在以后查看、筛选、编辑或删除。

## 方案比较

1. **独立模型与持久化（采用）**：大事由 `MilestoneModel` 管理，通过独立 `MilestoneStore` 保存；边界清晰且不会污染账本。
2. **复用账本数据结构**：可以少建一个存储，但人生事件与收入结算含义完全不同，容易形成错误耦合。
3. **仅使用页面状态**：实现最少，但弹窗关闭或应用重启后记录丢失，不符合长期记录用途。

## 数据与分类

每条 `Milestone` 包含：

- 稳定 UUID 标识。
- 事件日期 `date`。
- 去除首尾空白后的描述 `note`，保存时必须非空。
- 分类 `category`。
- 创建时间 `createdAt`，用于同日事件的稳定排序。

固定分类及 SF Symbols 图标：

- 工作：`briefcase.fill`
- 生活：`house.fill`
- 成长：`sparkles`
- 关系：`heart.fill`
- 健康：`cross.case.fill`
- 其他：`bookmark.fill`

分类是稳定的 Codable 枚举，不支持用户自定义；本次不加入提醒、附件、地点或云同步。

## 架构与隔离

- `MilestoneStore` 使用 `cowHorseClock.milestones.v1` 独立 UserDefaults 键保存 `[Milestone]`。
- `MilestoneModel` 独立拥有记录列表、增删改操作和排序逻辑。
- `CowHorseClockApp` 创建并注入 `MilestoneModel`，生命周期与菜单栏应用一致。
- `AppRoute` 只增加 `.milestones` 导航值；`AppModel` 不持有大事数据。
- `MilestoneView` 不读取 `snapshot`、`ledgerStore`、`EarningsEngine` 或 `FocusTimerModel`。

## 导航与页面

- 仪表盘标题栏新增薄荷色旗帜按钮，帮助文本为“人生大事”。
- 点击进入独立 `LIFE EVENTS` 页面，返回按钮回到仪表盘。
- 页面宽度 360、高度 560，与账本相同但保持自己的信息结构。
- 顶部显示总记录数和今年记录数，下面提供“全部”及六种分类筛选。
- 记录卡片按日期倒序排列；同一天按创建时间倒序排列。
- 每张卡片显示分类图标、分类名、日期和完整描述，使用 18 圆角、柔和对角渐变、渐变描边、轻微阴影及悬浮凸起。
- 空列表显示独立空状态与新建引导，不显示任何薪资文案。

## 新建、编辑与删除

- 页面右上角加号进入该功能内部的编辑界面，不使用设置页或系统独立窗口。
- 编辑器包含日期选择器、六种分类按钮和多行描述输入框。
- 新建默认日期为今天、分类为生活。
- 保存时对描述执行首尾空白清理；结果为空时保存按钮禁用。
- 点击已有卡片进入编辑；保存时保留原 UUID 和创建时间。
- 编辑已有记录时提供红色“删除这件大事”按钮，删除后返回列表。
- 取消编辑不会改动已有数据。

## 错误处理

- 存储数据缺失或无法解码时回退为空列表，应用继续可用。
- JSON 编码失败时不覆盖已有 UserDefaults 数据。
- 页面操作只在成功写入模型后返回列表；当前存储采用本地 UserDefaults，不新增用户可见错误弹窗。

## 测试与验收

- 测试分类名称与图标映射。
- 测试新增时清理描述、拒绝空描述、按日期与创建时间排序。
- 测试编辑保留标识与创建时间，测试删除。
- 测试独立持久化往返和损坏数据回退。
- 测试独立路由、环境注入、仪表盘入口，以及页面不引用薪资、账本或专注模型。
- 测试页面包含所有分类和新增、编辑、删除入口。
- 渲染检查列表与编辑状态，确认 360×560 菜单栏面板内无截断。
- 全量功能测试、图标契约、Release 构建、Info.plist 和代码签名验证必须通过。
- 禁止调用 `pdftotext`。
